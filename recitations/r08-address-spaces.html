Every address is a story

Lecture 13 stated that the addresses a program uses are logical, and that the MMU translates and checks them on every access. In this recitation, you observe this directly. First, the addresses move from run to run. Second, they sit in regions with permissions. Third, the same address holds two different values in two processes. Fourth, the hardware stops a write to code. After that, we help with Lab04.

Part 1 · follow along

Addresses move

/* where.c */#include <stdio.h>#include <stdlib.h>#include <unistd.h> int global = 1; int main(void) { int local = 2; int *heap = malloc(sizeof *heap); *heap = 3; printf("code %p\n", (void *)main); printf("global %p\n", (void *)&global); printf("heap %p\n", (void *)heap); printf("stack %p\n", (void *)&local); return 0;}
gcc -Wall -Werror -o where where.c && ./where && ./wheresetarch -R ./where ; setarch -R ./where
What you should see

Two plain runs print different numbers, for example code 0x563849841149 and then 0x563aa1d52149. However, the order is always the same, namely code < global < heap, and all three lie far below the stack near 0x7ff…. With setarch -R, both runs are identical, with code at 0x555555555149 and the stack at 0x7fffffffec04.

On every run, the kernel places each region at a random base. This is address space layout randomization. As a result, an attacker cannot predict where code and data are. setarch -R turns it off for one run. Note that the program runs correctly wherever it is placed. This is execution-time binding.

Each line is a start–end range with protection bits. In other words, each line gives the base, limit, and permissions of a segment (Lecture 13, §5). Code is r-x, which means readable and executable but not writable. Data, heap, and stack are rw-. p means private to this process. ld-linux is the dynamic linker from Lecture 13, §1.4.

Part 3 · follow along

One address, two values

/* twins.c */#include <stdio.h>#include <unistd.h>#include <sys/wait.h> int global = 1; int main(void) { if (fork() == 0) { global = 99; printf("child: &global = %p global = %d\n", (void *)&global, global); return 0; } wait(NULL); printf("parent: &global = %p global = %d\n", (void *)&global, global); return 0;}
child: &global = 0x5629ef66e028 global = 99parent: &global = 0x5629ef66e028 global = 1
How can one address hold two values?

It is one logical address in two different address spaces. For each process, the MMU maps this address to a different physical location. In R03, you saw that the child's copy is separate. This mapping is the reason.

Part 4 · follow along

Protection

/* poke.c */#include <stdio.h> int main(void) { unsigned char *p = (unsigned char *)main; fprintf(stderr, "first byte of main: 0x%02x\n", *p); /* reading code is allowed */ *p = 0; /* writing it is not */ printf("not reached\n"); return 0;}

It prints first byte of main: 0x55 and then Segmentation fault, and echo $? prints 139. The code region is r-x. Therefore, the write traps to the kernel, and the kernel kills the process with SIGSEGV. This is the protection check of Lecture 13, §2.1, which the hardware performs on every access.

The first line goes to stderr on purpose. If it went to stdout and stdout were redirected to a file, the line could still be in the buffer when the process dies (R03).
