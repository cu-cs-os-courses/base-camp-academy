Part 1 · follow along

The inode

cd /tmpecho hello > a.txtstat a.txtls -i a.txtls -ia /tmp | head -5
# from the course VM (your numbers may differ) File: a.txt Size: 6 Blocks: 8 IO Block: 4096 regular fileDevice: 253,0 Inode: 9485 Links: 1Access: (0644/-rw-r--r--) Uid: ( 0/ root) Gid: ( 0/ root)…9485 a.txt
  • The inode holds the metadata, namely size, owner, mode, timestamps and the block map. It does not hold the name.
  • ls -ia shows a directory's entries, including . and ... A directory is a file whose contents are pairs of (name, inode number).
  • Size: 6 but Blocks: 8 means 8 × 512 bytes, one whole 4 KB block, for 6 bytes of data. The smallest allocation is a block.
Part 2 · follow along

Hard and symbolic links

ln a.txt b.txtls -li a.txt b.txtrm a.txtcat b.txtln -s b.txt c.txtls -li b.txt c.txtrm b.txtcat c.txtls -l c.txt
What you should see, and why
  • After ln, both names show inode 9485 and link count 2. That is two directory entries and one file.
  • After rm a.txt, cat b.txt still prints hello. rm removes a name. The inode and its blocks are freed only when the link count reaches 0 and no process has the file open.
  • c.txt is a different inode (9486), type l, size 5. Its data is the five characters b.txt.
  • After rm b.txt, cat c.txt fails with No such file or directory, but ls -l c.txt still shows c.txt -> b.txt. A symbolic link is a path, looked up at every open, and it can dangle.
Part 3 · follow along

Find the data on the disk

cd /rootecho "hello, disk" > note.txtsync # make sure it reached the diskdebugfs -R "stat /root/note.txt" /dev/vda # read-only by defaultdebugfs -R "blocks /root/note.txt" /dev/vda
# from the course VMInode: 9485 Type: regular Mode: 0644 Flags: 0x80000User: 0 Group: 0 Project: 0 Size: 12Links: 1 Blockcount: 8…EXTENTS:(0):186368

Logical block 0 of the file is physical block 186368 of the disk. Read that block straight from the device, bypassing the file system (use the number your VM printed) with the command below.

dd if=/dev/vda bs=4096 skip=186368 count=1 2>/dev/null | head -c 12; echohello, disk

There is nothing magic about a file. It is bytes in known blocks, and the inode is the map. Next come a large file and a directory read straight from disk.

filefrag -v /usr/bin/bashdebugfs -R "ls -l /root" /dev/vda
File size of /usr/bin/bash is 1265648 (309 blocks of 4096 bytes) ext: logical_offset: physical_offset: length: expected: flags: 0: 0.. 308: 9372.. 9680: 309: last,eof/usr/bin/bash: 1 extent found

309 blocks in one extent form a single contiguous run, which is what ext4's extent-based allocation aims for (Lecture 20). debugfs ls -l lists the directory's entries with their inode numbers, read from the disk rather than through the kernel's caches.

Clean up afterwards with rm /root/note.txt, because /root persists in your VM image, while /tmp is cleared at every boot.

Cheat sheet

stat f · ls -i fInode number, size, blocks, link count, times.
ln a b · ln -s a bHard link (same inode) · symbolic link (new inode holding the path).
debugfs -R "stat /path" /dev/vdaThe inode as stored on disk, including its extents.
debugfs -R "blocks /path" /dev/vdaJust the file's physical block numbers.
filefrag -v fHow many extents (contiguous runs) a file uses.
dd if=/dev/vda bs=4096 skip=N count=1Read disk block N directly.
syncFlush cached writes to the disk.
