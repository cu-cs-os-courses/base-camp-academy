Part 1 · follow along

The smallest useful module

/* hello.c */#include <linux/init.h>#include <linux/module.h> MODULE_LICENSE("GPL");MODULE_DESCRIPTION("R11 demo: the smallest useful module"); static int count = 1;module_param(count, int, 0444);MODULE_PARM_DESC(count, "how many times to say hello"); static int __init hello_init(void){ int i; for (i = 0; i < count; i++) pr_info("hello: loaded (%d of %d)\n", i + 1, count); return 0;} static void __exit hello_exit(void){ pr_info("hello: unloaded\n");} module_init(hello_init);module_exit(hello_exit);
  • There is no main. module_init names the function the kernel calls on load, and module_exit the one it calls on unload. A nonzero return from init means "failed to load".
  • There is no printf: the kernel has no terminal. pr_info (a printk) writes to the kernel log.
  • module_param makes count settable when the module is loaded.
  • Once loaded, this code runs in kernel mode. A bug here can crash the whole VM, not just one process.
Part 2 · follow along

Build it, on the laptop

A module is built against one exact kernel tree. The VM has none, so the build runs in the course's Docker container, just as in Lab05. Docker must be running.

# repository root; the directory must be inside the repo (Docker's file sharing)mkdir -p mod-r11 && cp hello.c mod-r11/ && printf 'obj-m := hello.o\n' > mod-r11/Makefiledocker run --rm --platform linux/amd64 \ -v kernel-lens-cache:/work/cache -v "$PWD/mod-r11:/mod" kernel-lens-build \ sh -c 'make -C /work/cache/linux-6.6.87 M=/mod modules \ && objcopy --remove-section .BTF /mod/hello.ko'SHARE=$PWD/mod-r11 env/run.sh # boot with the module at /share

If Docker reports that the image kernel-lens-build is missing, run make images in env/. The objcopy step is explained in the Lab05 README.

Load it, look at it, unload it

modinfo /share/hello.koinsmod /share/hello.ko count=3dmesg | tail -3lsmod | head -3cat /sys/module/hello/parameters/countrmmod hellodmesg | tail -1
# from the course VMdescription: R11 demo: the smallest useful moduleparm: count:how many times to say hello (int)vermagic: 6.6.87 SMP preempt mod_unload[ 3.685538] hello: loaded (1 of 3)[ 3.685881] hello: loaded (2 of 3)[ 3.685954] hello: loaded (3 of 3)hello 12288 03[ 3.779600] hello: unloaded
  • vermagic records the kernel the module was built for. The kernel refuses a module whose vermagic does not match it.
  • lsmod shows the module's size and how many users it has (0).
  • Loaded parameters show up under /sys/module/<name>/parameters/.
  • insmod and rmmod make system calls underneath (init_module, delete_module), and only root may make them.
Part 4 · follow along

How a device file finds its driver

ls -l /dev/null /dev/zero /dev/ttyhead -12 /proc/devices
crw-rw-rw- 1 root root 1, 3 … /dev/nullcrw-rw-rw- 1 root tty 5, 0 … /dev/ttycrw-rw-rw- 1 root root 1, 5 … /dev/zeroCharacter devices: 1 mem 4 tty 5 /dev/tty …

The c means character device, and in place of a size ls shows two numbers. The major picks the driver; /proc/devices lists which driver owns which major. The minor picks a device within that driver. A file in /dev is only a name for a (major, minor) pair. open on it dispatches to whichever driver registered that major. In Lab05 Part 2 you register major 511 and create such a name yourself.
