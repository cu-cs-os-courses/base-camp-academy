One call, two returns

Lecture 03 introduced the three calls every process lives by. fork copies a process, exec replaces its program, and wait collects its child's exit status. Today you predict what fork does before running it, watch a shell use all three, and make a zombie without writing any C. Then Lab01 help.

Part 1 · follow along

Predict, then run

Before you run each program, write down what you think it prints.

/* fork1.c */#include <stdio.h>#include <unistd.h>#include <sys/wait.h> int x = 1; int main(void) { pid_t p = fork(); if (p == 0) { x = 10; printf("child: pid=%d fork returned %d x=%d\n", getpid(), p, x); } else { wait(NULL); printf("parent: pid=%d fork returned %d x=%d\n", getpid(), p, x); } return 0;}
What you should see, and why
child: pid=412 fork returned 0 x=10parent: pid=411 fork returned 412 x=1
  • fork is called once and returns twice. It returns 0 in the child and the child's PID in the parent. That value is how each copy knows which one it is.
  • The child changed x, but the parent did not see it. After fork, the two have separate copies of all memory.
  • Delete wait(NULL) and run it several times. The order of the two lines is no longer fixed. The scheduler decides.
/* fork2.c */#include <stdio.h>#include <unistd.h> int main(void) { printf("A"); /* no newline */ fork(); printf("B\n"); return 0;}
What you should see, and why

AB, twice. printf("A") ran once, but it only put A in the stdio buffer, which lives in the process's memory. fork copied that memory, buffer included, and each process flushed its own copy when it exited.

Change it to printf("A\n"). On the terminal, A now prints once. A terminal is line-buffered, so the newline flushed it before the fork. Now run ./fork2 > out.txt; cat out.txt. It is twice again, because a file is fully buffered. Remember this when Lab01 warns you about buffering.

Part 2 · follow along

A shell, traced

strace -o /tmp/f.txt -f -e trace=clone,execve,wait4,exit_group bash -c '/bin/true; /bin/false; echo $?'cat /tmp/f.txt
195 clone(…) = 196195 wait4(-1, <unfinished ...>196 execve("/bin/true", ["/bin/true"], …) = 0196 exit_group(0) = ?195 <... wait4 resumed>[{WIFEXITED(s) && WEXITSTATUS(s) == 0}], 0, NULL) = 196195 --- SIGCHLD {si_signo=SIGCHLD, si_code=CLD_EXITED, si_pid=196, …} ---195 clone(…) = 197195 wait4(-1, <unfinished ...>197 execve("/bin/false", ["/bin/false"], …) = 0197 exit_group(1) = ?195 <... wait4 resumed>[{WIFEXITED(s) && WEXITSTATUS(s) == 1}], 0, NULL) = 197… (a few lines shortened; your PIDs differ)
  • clone is how Linux implements fork, and the C library's fork() calls it. -f makes strace follow the children, and each line starts with the PID that made the call. -o keeps the trace out of the shell's own output.
  • <unfinished ...> … resumed means the parent blocked in wait4 while the child ran.
  • For each command, the shell forks. The child calls execve and becomes /bin/true. The parent waits in wait4 and gets back the exit status, first 0 and then 1.
  • echo is built into the shell, so it needs no fork at all.
  • You may also see --- SIGCHLD … --- lines. That is the kernel signaling the shell that a child finished, one of Thursday's IPC mechanisms.
Part 3 · follow along

A zombie, without writing C

bash -c 'sleep 2 & exec sleep 60' &sleep 3; ps -o pid,ppid,stat,comm --ppid $!kill %1 # clean up

bash starts sleep 2 in the background, then execs itself into sleep 60, a program that never calls wait. When sleep 2 exits, it cannot disappear, because its exit status is still waiting to be collected. ps shows it in state Z, a zombie that is dead but still in the process table.

Cheat sheet

pid_t fork(void)Copy the calling process. Returns 0 in the child, the child's PID in the parent, −1 on failure.
exec…()Replace the current program. Returns only if it failed.
wait / waitpidWait for a child to end and collect its status. See wait(2).
getpid() · getppid()My PID · my parent's PID.
strace -fTrace a program and every child it forks.
ps -o pid,ppid,stat,commShow chosen columns. STAT is the state (R running, S sleeping, Z zombie).
cmd & · $! · kill %1Run in background · its PID · kill background job 1.
