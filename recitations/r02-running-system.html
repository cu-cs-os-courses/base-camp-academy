Two doors into the kernel

Lectures 01–02 said a program talks to the kernel only through system calls, and that the kernel runs in a mode your code cannot enter. Today you watch both happen. /proc shows the kernel's own state as files, and strace shows every system call a program makes. Then the second half is Lab00 help: it is due Sunday.

Part 1 · follow along

/proc is not on the disk

In the VM:

mount | grep ' /proc ' # proc on /proc type proc (...)ls -l /proc/uptime # size 0 ...cat /proc/uptime # ... yet it prints textsleep 2; cat /proc/uptime # and the text changes
A virtual file system

Nothing in /proc is stored anywhere. When you read a file, the kernel generates its contents on the spot from its own data structures. That is why the size is 0 and why the numbers change. The first number in uptime is seconds since boot.

Every process has a directory named by its PID:

sleep 300 & # start one in the background; $! is its PIDls /proc/$!grep -E '^(State|PPid|Threads)' /proc/$!/statusls -l /proc/$!/fd # its open fileskill %1

fd holds 0, 1 and 2, pointing to your terminal: every process starts with standard input, output and error as file descriptors 0, 1 and 2. These are the numbers behind 2>&1 in R01.

Part 2 · follow along

Watching system calls

/* hello.c */#include <stdio.h>int main(void) { printf("hello\n"); return 0; }
gcc -Wall -Werror -o hello hello.cstrace -o /tmp/t.txt ./hello # trace into a filetail -3 /tmp/t.txt

The last three lines of the trace are what main did:

write(1, "hello\n", 6) = 6exit_group(0) = ?+++ exited with 0 +++
  • printf is a library function. The only thing that reached the kernel was a write to file descriptor 1. return 0 became exit_group(0).
  • Everything above those lines (execve, mmap, openat of libc.so.6, …) is the program being loaded, before main ran.

Now a program you did not write:

strace -o /tmp/u.txt -e trace=openat,read,write,close cat /proc/uptimeless /tmp/u.txt # q to quit
… ld.so.cache and libc.so.6 (the loader), then ~30 locale files (LC_*): ignore …openat(AT_FDCWD, "/proc/uptime", O_RDONLY) = 3read(3, "1234.56 1180.02\n", 131072) = 16write(1, "1234.56 1180.02\n", 16) = 16read(3, "", 131072) = 0close(3) = 0close(1) = 0close(2) = 0

That is the whole of cat: open, read, write, and read again until read returns 0 (end of file). 3 is the next free descriptor after 0, 1 and 2. One more:

strace -c ls / > /dev/null # a table: which system calls, how many times

Every use of files, memory, other processes or the network appears in strace. There is no other door into the kernel.

Cheat sheet

strace ./progPrint every system call prog makes, with arguments and return values.
strace -o file …Write the trace to a file instead of mixing it with the program's output.
strace -e trace=openat,read …Only the listed system calls.
strace -c …A summary table instead: count and time per system call.
strace -f …Follow child processes too (useful from Lab01 on).
/proc/<pid>/statusA process's state, parent, threads and memory, in readable form.
/proc/<pid>/fd/Its open file descriptors, as links to what they refer to.
