T0's request is the one to remember. One instance of C is free, T0 is allowed to ask for it, and it must still wait, because taking it would leave no thread able to finish. The Banker's algorithm refuses to enter an unsafe state even when the resources are sitting there.

Part 2 · follow along

Cycle or deadlock?

Graph 1. R1 has 1 instance, R2 has 2, R3 has 1.

  • T1 holds R1, requests R2.
  • T2 holds one R2, requests R3.
  • T3 holds one R2 and R3, requests R1.

Graph 2. The same, but R2 has 3 instances, and a fourth thread T4 holds one R2 and requests nothing.

Graph 1: find the cycles, then reduce

Cycles: T1 → R2 → T2 → R3 → T3 → R1 → T1, and T1 → R2 → T3 → R1 → T1. Free instances: R1 0, R2 0, R3 0. Nobody's request can be met, so T1, T2 and T3 are deadlocked.

Graph 2: same cycles; reduce
  1. T4 requests nothing, so it finishes and frees an R2.
  2. T1 gets that R2, finishes, and frees R1 and R2.
  3. T3 gets R1, finishes, and frees R2 and R3.
  4. T2 gets R3 and finishes.

No deadlock. With several instances per resource, a cycle is necessary but not sufficient: reduce the graph to decide. With one instance per resource, a cycle is a deadlock.

Cheat sheet

four conditionsMutual exclusion, hold and wait, no preemption, circular wait: all at once.
AvailableTotal − sum of Allocation.
NeedMax − Allocation.
safety algorithmRepeatedly pick an unfinished thread with Need ≤ Work; Work += its Allocation. Safe if all finish.
request algorithm≤ Need, else error; ≤ Available, else wait; pretend and run safety; unsafe → wait.
graph reductionLet any thread whose requests can be met finish and free its resources; whoever is left is deadlocked.
cycleOne instance per type: deadlock. Several: maybe; reduce.
