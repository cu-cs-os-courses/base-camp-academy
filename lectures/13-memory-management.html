Where does a program live?

A process uses addresses, and memory has addresses, but they need not be the same numbers. This lecture follows an address from source code to a memory chip: when it is bound, how hardware checks and relocates it, how the OS carves physical memory among processes, and what goes wrong when it does so in contiguous pieces. That failure motivates paging in Lecture 14.

Chapter 0

Background

The CPU can only touch registers and main memory, and memory is slow.

0.1What the CPU sees

  • A program must be brought from disk into memory, and placed within a process, before it can run.
  • Main memory and registers are the only storage the CPU accesses directly. The memory unit just sees a stream of address + read requests and address + data + write requests. It does not know which is code, data or stack.
  • A register access takes one CPU clock or less; main memory can take many cycles and stall the CPU. Caches sit in between.
  • Memory must be protected, so that a process touches only its own addresses (§2).

0.2The memory hierarchy

Chapter 1

Address binding

A name in source code becomes a number in memory. The question is when.

1.1From symbol to address

  • Programs on disk waiting to be brought into memory form an input queue. Without hardware support, a program would have to be loaded at physical address 0000, which is inconvenient: only one program could live there.
  • Addresses take different forms at different stages of a program's life:
    • source code: symbolic, like count;
    • the compiler binds them to relocatable addresses: "14 bytes from the beginning of this module";
    • the linker or loader binds those to absolute addresses: 74014.
  • Each binding maps one address space to another.

1.2Three binding times

Compile timeIf the memory location is known in advance, the compiler generates absolute code. If the starting location changes, you must recompile.
Load timeIf the location is not known at compile time, the compiler generates relocatable code, and the loader fixes the addresses. To move the program, reload it.
Execution timeBinding is delayed until run time, so the process can be moved during execution from one memory region to another. This needs hardware support: base and limit registers, or an MMU (§2). Nearly every modern OS works this way.
Try itMove a running program

1.3Logical vs. physical addresses

  • A logical address, also called a virtual address, is generated by the CPU. A physical address is what the memory unit sees.
  • With compile-time and load-time binding they are the same. With execution-time binding they differ.
  • The logical address space is the set of all logical addresses a program generates. The physical address space is the set of physical addresses those correspond to.

1.4Dynamic loading and dynamic linking

Dynamic loading

The whole program does not need to be in memory to run. A routine is loaded only when it is first called; unused routines, such as rare error handlers, are never loaded. Routines wait on disk in relocatable form. No special OS support is required: it is done by program design, perhaps with OS-provided library help (e.g. dlopen()).

Dynamic linking

Static linking copies library code into the binary image. Dynamic linking postpones linking until run time. A small stub locates the memory-resident library routine, replaces itself with the routine's address, and calls it; the OS maps the library into the process if it is not already there. These are shared libraries (.so, .dll). One copy serves every process, and patching the library fixes every program, which is why versioning is needed.

Chapter 2

Protection and the MMU

Two registers, checked on every memory access.

2.1Base and limit

  • A process must access only addresses in its own address space. A pair of registers defines that space: base, the smallest legal physical address, and limit, the size of the range.
  • The CPU checks every memory access made in user mode: base ≤ address < base + limit. Anything else traps to the OS as an addressing error.
  • The instructions that load base and limit are privileged. Only the kernel sets them, as part of each context switch.

2.2The memory-management unit

  • The MMU is the hardware that maps virtual addresses to physical ones at run time. It must do two things: translate addresses and check bounds.
  • The simplest scheme generalizes the base register into a relocation register: its value is added to every address a user process generates, at the moment the address is sent to memory. With a limit register as well, each logical address must be less than the limit, and physical = logical + relocation.
  • The user program deals only with logical addresses and never sees the physical ones. Binding happens at the moment of each memory reference: execution-time binding.

Chapter 3

Contiguous allocation

Give each process one piece of memory, then watch memory crumble.

3.1Partitions and holes

  • Main memory holds both the OS and user processes, and it is limited, so it must be allocated efficiently. Contiguous allocation is an early method. The resident OS is usually in low memory, with the interrupt vector; user processes are in high memory, each in a single contiguous section.
  • Relocation and limit registers protect processes from each other and from the OS. They are loaded only in kernel mode, during context switches. Because the MMU maps addresses dynamically, even the kernel can change size.
  • Variable partitions are sized to each process's needs. A hole is a block of available memory, and holes of various sizes are scattered through memory. A new process gets part of a hole large enough for it. When a process exits, its partition becomes a hole, merged with any adjacent holes. The OS tracks allocated partitions and free holes.

3.2Which hole?

First fitTake the first hole that is big enough. It is fast.
Best fitTake the smallest hole that is big enough. It must search the whole list unless the list is sorted, and it leaves the smallest leftover.
Worst fitTake the largest hole. It also searches everything, and it leaves the largest leftover, hoping that piece is still useful.
Next fitTreat the holes as a circular list, and start the first-fit search just after the hole chosen last time.

3.3Fragmentation

  • As processes come and go, free memory breaks into pieces.
  • External fragmentation: there is enough total free memory for a request, but it is not contiguous. You saw it above when 426 KB failed.
  • Internal fragmentation: memory is handed out in fixed-size units, so an allocation can be slightly larger than the request. The unused difference is inside a partition and wasted. Example: a request for 18,462 bytes against a 18,464-byte hole. Keeping track of the 2-byte leftover would cost more than it saves, so the OS gives the whole hole.
  • Both first fit and best fit suffer external fragmentation. Best fit leaves many slivers too small to use. First fit tends to fragment the low end of memory, where it always starts. Statistically, with first fit, about half as much memory again as is allocated is lost to fragments: the 50-percent rule, which means up to a third of memory may be unusable.

3.4Compaction

  • Reduce external fragmentation by compaction: shuffle memory contents so that all free memory forms one large block. It is expensive, since every moved byte is copied.
  • It is possible only if relocation is dynamic, done at execution time: moving a process just updates its relocation register.
  • I/O complicates it. A device doing DMA into a process's buffer uses physical addresses, so that job must be latched in memory while the I/O is in progress. The alternative is to do I/O only into OS buffers.

Chapter 4

Swapping

When memory runs out, move a whole process to disk.

4.1Swap out, swap in

When the scheduler selects P2, the dispatcher checks whether P2 is in memory. If it is not and there is not enough free memory, it swaps out some process, say P3, to the backing store and swaps in P2.

  • It is slow. Disk access takes about 10–100 ms, and transferring a whole process adds size ÷ bandwidth. A 100 MB process at 50 MB/s takes 2 s each way, so 4 s to swap one out and another in.
  • Try to hide the latency. In round robin, swap out the process that just ran, and keep enough other processes in memory to run while the swap-in completes. It cannot be hidden if the in-memory processes are all blocked on I/O.
  • A process with pending I/O is a problem: the device may still write into its memory. One simple rule is to never swap such a process.
  • Swapping fragments main memory, and the backing store too.
Today

Modern systems avoid swapping whole processes unless memory use crosses a threshold. Instead they swap portions of processes, pages, together with virtual memory and demand paging (Lectures 14–16). Mobile systems such as iOS and Android usually do not swap at all; they ask apps to free memory, or terminate them.

Chapter 5

Segmentation

Instead of one big contiguous piece, several smaller ones, each with its own base and limit.

5.1A program is a collection of segments

  • A programmer thinks of a program as a main function, other functions, a library, a stack, a heap and data, not as one flat array. Segmentation gives each of these its own segment, placed anywhere in physical memory.
  • A logical address is a pair (s, d): segment number and offset. A segment table gives each segment's base and limit.
  • Check d < limit[s], or trap; otherwise physical = base[s] + d. It is the relocation-and-limit MMU of §2, once per segment.
  • Segments are smaller than whole processes, so they fit into holes more easily. But segments still vary in size, so external fragmentation remains. Fixed-size pieces, pages, fix that in Lecture 14.

Epilogue

Summary and glossary

∎What to take away

  • The CPU accesses only registers and memory; caches bridge the speed gap in a hierarchy that gets slower, bigger and cheaper as it goes down.
  • Addresses go from symbolic to relocatable to absolute. Binding can happen at compile time, at load time, or at execution time, which needs an MMU.
  • Base and limit registers, loaded only by the kernel, check every user access. A relocation register adds a base to every logical address.
  • Dynamic loading loads routines when first called; dynamic linking shares libraries through stubs.
  • Contiguous allocation takes holes by first, best, worst or next fit, and suffers external fragmentation, which compaction can reduce. Allocating in fixed units causes internal fragmentation.
  • Swapping moves whole processes to disk; it is slow. Segmentation splits a process into variable-size segments, each with its own base and limit, which leads to paging.
