Which page goes?

Lecture 15 ends at step 2(b), where no frame is free and the OS must pick a victim. In this lecture, we compare the ways to pick it. First-in first-out is simple, but it sometimes behaves perversely. The optimal policy needs to see the future. Least-recently-used is the practical ideal. However, it is too costly to track exactly. Therefore, real systems approximate it with a single hardware bit and a clock hand.

Chapter 0

Evaluating a replacement policy

Count faults on a reference string.

0.1Reference strings

  • An algorithm is judged by three variables, namely the algorithm itself, the page reference sequence, and the number of frames. The best algorithm is the one with the fewest page faults.
  • A reference string lists only the page numbers that a process touches, in order. Consecutive references to the same page are collapsed into one, because the second reference cannot fault.
  • The running example is the string from the textbook, with 3 frames per process, as shown below.

7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1

Chapter 1

FIFO, OPT, and LRU

Oldest arrival, farthest future, or longest idle.

1.1Three policies

FIFOReplace the page that has been in memory the longest. A simple FIFO queue tracks the ages. FIFO takes 15 faults on the example.
Optimal (OPT)Replace the page that will not be used for the longest time in the future. OPT has the fewest possible faults, namely 9. It cannot be implemented, because the OS cannot read the future. However, it is the yardstick for measuring the other policies.
LRUUse the past as a guess about the future. Specifically, replace the page that has gone unused the longest. This requires a time of last use for each page. LRU takes 12 faults, which is better than FIFO and worse than OPT. It is generally good and widely used. However, it is not obvious how to implement it.

FIFO can perform very poorly, because age says nothing about use. If page 7 is referenced often, FIFO still evicts it once it is the oldest, and it faults back in again and again. In the worst case, every page paged out is the very next one needed. Ideally, the OS keeps the pages that are about to be used.

Chapter 2

Belady's anomaly

More memory can mean more faults. However, this happens only with some algorithms.

2.1Faults vs. frames

One expects more frames to mean fewer faults. However, for FIFO, this is not guaranteed. On the string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5, FIFO takes 9 faults with 3 frames but 10 with 4. This is Belady's anomaly. In contrast, LRU and OPT are stack algorithms. The pages in memory with n frames are always a subset of those with n + 1. As such, adding frames can never add a fault. Clock is built on FIFO order and is not a stack algorithm. Therefore, it can show the anomaly too.

Chapter 3

Implementing LRU

Exact LRU is expensive. However, one hardware bit gets surprisingly close.

3.1Exact LRU

Keep a historyRecord past page accesses, either the entire history, which takes a lot of memory, or a sliding window. Either way, it is complicated and slow.
TimestampsStore the time of last use in each page-table entry. This is expensive in delay (read the clock on every memory reference), in storage (at least 64 bits per timestamp), and in search (find the oldest at replacement time).
A stack of page numbersOn each reference, move the page to the top of a doubly linked list. The LRU page is always at the bottom, so no search is needed. However, every memory reference updates several pointers.
The real obstacleAll of these do work on every memory reference, which means billions of times per second. This would need special hardware. Therefore, systems actually use variations of LRU that approximate it cheaply.

3.2Reference bits and the clock algorithm

  • The hardware sets a page's reference bit to 1 whenever the page is accessed (Lecture 15, §3.3). The OS can clear it. Note that the bit does not say when a page was used. It says only whether the page was used since the bit was last cleared.
  • Second chance is FIFO, except that a page whose reference bit is 1 is spared. Instead, its bit is cleared, and the page goes to the back of the queue.
  • The clock algorithm implements second chance with the frames arranged in a circle and a hand. On a fault, the hand sweeps. A frame with bit 1 is cleared and skipped, and the first frame with bit 0 is the victim. As such, a page used since the last sweep survives one more round. If every bit is 1, the hand goes all the way around, and the algorithm degenerates to FIFO.
  • Clock costs one bit per page and no work on hits. In practice, Linux, BSD, and Windows use variants of clock, often combined with the dirty bit to prefer clean victims.

Epilogue

Summary and glossary

∎What to take away

  • A replacement policy is evaluated by counting faults on a reference string for a given number of frames.
  • On the textbook string with 3 frames, FIFO takes 15 faults, LRU takes 12, and OPT takes 9.
  • FIFO ignores use and can suffer Belady's anomaly. In contrast, LRU and OPT are stack algorithms, and they cannot suffer it.
  • OPT cannot be implemented, but it defines the lower bound. LRU approximates OPT from the past.
  • Exact LRU (history, timestamps, stack) costs work on every reference. Reference bits and the clock (second-chance) algorithm approximate it cheaply.
