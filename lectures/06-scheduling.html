Chapter 0

Bursts and the CPU scheduler

Processes alternate between computing and waiting. The scheduler fills the gaps.

0.1The CPU–I/O burst cycle

  • Multiprogramming maximizes CPU utilization (Lecture 01).
  • A process's execution is a cycle of CPU bursts and I/O bursts. In other words, it computes, waits for I/O, computes, waits for I/O, and so on.
  • The distribution of CPU-burst lengths matters most. Specifically, there are many short bursts and few long ones. An I/O-bound program has many short bursts. In contrast, a CPU-bound program has a few long ones.

0.2When does the scheduler run?

The CPU scheduler selects a process from the ready queue and gives it a core. A decision may be needed when a process does one of the following.

  1. switches from running to waiting (an I/O request, wait()),
  2. switches from running to ready (an interrupt),
  3. switches from waiting to ready (I/O completes), or
  4. terminates.

In cases 1 and 4, there is no choice. The core is free, so the scheduler must pick a new process. In cases 2 and 3, there is a choice. The scheduler can keep the current process or switch to another one.

0.3Preemptive or not

  • Scheduling only in cases 1 and 4 is nonpreemptive. Once a process has the CPU, it keeps it until it terminates or waits.
  • Otherwise, it is preemptive. In other words, the OS may take the CPU away from a running process. Virtually all modern OSes (Windows, macOS, Linux, UNIX) are preemptive.
  • Note that preemption is the reason that shared data can suffer race conditions. A thread can be stopped at any point (Lecture 05, and Lectures 08–11).

Chapter 1

Mechanism, how to switch

The scheduler picks a process. The dispatcher performs the switch.

1.1The dispatcher

  • The dispatcher gives the CPU to the process that the scheduler selected. Specifically, it switches context, switches to user mode, and jumps to the right place in the user program.
  • Dispatch latency is the time it takes to stop one process and start another. For example, a latency of 10 µs on a 1 GHz CPU wastes 10,000 cycles per switch.

1.2A function that returns into another process

A context switch is a function call that returns asynchronously. Process A calls it. However, process B continues after the return. First, it saves all registers in a scratch area (the process's kernel stack or its task_struct). Second, it switches address spaces. Third, it restores the new process's registers and returns to B.

Chapter 2

Policy, scheduling criteria

Before we compare algorithms, we define what "better" means.

2.1Five measures

  • CPU utilization. Keep the CPU as busy as possible (40%–90% in practice).
  • Throughput. The number of processes completed per time unit.
  • Execution (burst) time. The CPU time needed to run the process to completion.
  • Waiting time. The time spent in the ready queue without running. Note that it does not include time spent waiting for I/O.
  • Turnaround time. The time from first entering the ready queue to finally exiting. It includes both waiting and I/O.
  • Response time. The time from first entering the ready queue to first running. It matters for interactive tasks.
Goals

We want to maximize utilization, throughput, and fairness, meet deadlines, respect priorities, and minimize turnaround, waiting, and response time. However, no single algorithm achieves all of these goals. For the analysis below, we assume no blocking I/O. As such, each process runs one burst to completion.

Chapter 3

First-come first-served and shortest job first

The simplest policy, and the one that is provably best at waiting time.

3.1FCFS and the convoy effect

  • First-come, first-served. The scheduler runs processes in arrival order, each to completion. For example, if P1 = 24, P2 = 3, and P3 = 3 arrive in that order, the waiting times are 0, 24, and 27, with an average of 17.
  • If the same processes arrive in the order P2, P3, P1, the waiting times are 6, 0, and 3, with an average of 3. This order is much better.
  • The convoy effect refers to short processes stuck behind a long one. Consider one CPU-bound process and many I/O-bound ones. The I/O-bound processes finish their I/O and then queue behind the CPU-bound process. Meanwhile, the devices sit idle.
  • FCFS is nonpreemptive, simple, and fair in arrival order. However, its waiting and response times are poor.

3.2SJF and SRTF

  • Shortest job first. The scheduler associates each process with the length of its next CPU burst and runs the shortest one. SJF is optimal, because it gives the minimum average waiting time for a given set of processes. For example, with P1 6, P2 8, P3 7, and P4 3, the order is P4, P1, P3, P2. The waiting times are 3, 16, 9, and 0, with an average of 7.
  • The preemptive version of SJF is shortest remaining time first (SRTF). Whenever a process arrives, SRTF decides again based on remaining time. For example, with P1 (0, 8), P2 (1, 4), P3 (2, 9), and P4 (3, 5), the average waiting time is 6.5.
  • However, SJF needs the length of the next burst. The OS can ask the user or estimate it (§3.4). Further, long jobs may starve behind a stream of short ones.

3.4Predicting the next burst

The OS can only estimate the next burst. We assume that the next burst resembles the previous ones and use an exponential average.

τn+1 = α · tn + (1 − α) · τn

Here, tn is the actual length of the n-th burst, τn is its prediction, and 0 ≤ α ≤ 1 (commonly ½).

  • With α = 0, τn+1 = τn, so recent history does not count.
  • With α = 1, τn+1 = tn, so only the last burst counts.
  • Expanding the formula gives τn+1 = α tn + (1−α) α tn−1 + … + (1−α)j α tn−j + … + (1−α)n+1 τ0. Each older term weighs less than the term after it.

Chapter 4

Round robin

It is not fair for a long process to use the CPU as long as it wants, nor for it to wait behind every shorter process. Instead, processes take turns.

4.1Time slices

  • Each process gets a small unit of CPU time, namely the time quantum q, usually 10–100 ms. When the quantum expires, the OS preempts the process and puts it at the end of the ready queue. A timer interrupt fires every quantum.
  • With n processes, each process gets 1/n of the CPU in chunks of at most q. Therefore, no process waits more than (n−1)q for its next turn.
  • A process can finish before its quantum ends. In that case, the scheduler takes the next process. For example, with P1 24, P2 3, P3 3, and q = 4, P1 runs 0–4, P2 runs 4–7, P3 runs 7–10, and then P1 runs to 30.
  • RR typically has a higher average turnaround than SJF. However, its response is much better. It is simple, because it only rotates and needs no burst lengths. It is also fair, because each process gets 1/n. As such, RR suits interactive systems and is popular.

4.2Choosing the quantum

  • If q is large, RR becomes FCFS. If q is small, there are many switches.
  • However, q must be large relative to the context-switch time. Otherwise, the overhead dominates. For example, a 10-unit job needs 0 switches with q = 12, 1 switch with q = 6, and 9 switches with q = 1.
  • Note that average turnaround does not improve steadily as q changes. As a rule of thumb, most CPU bursts (about 80%) should fit in one quantum.

4.3Weighted round robin

  • Weighted RR gives some tasks more quanta per round than others. This is one way to implement priorities (more in Lecture 07).
  • If Pi gets Ni quanta per round, its share of the CPU is
sharei = Ni / Σj Nj

In the example above, suppose P1 gets two quanta per round and P2 and P3 get one each. Then P1 gets 2/4 = 50% of the CPU while all three are running. You can try "Weighted RR" in §3.3.

Epilogue

Summary and glossary

∎What to take away

  • Processes alternate between CPU and I/O bursts. Most bursts are short.
  • The scheduler decides at four points. Deciding only when a process blocks or exits is nonpreemptive. The dispatcher performs the context switch, and the cost is the dispatch latency.
  • The criteria are utilization, throughput, turnaround, waiting, response, and fairness.
  • FCFS is simple. However, it suffers from the convoy effect. SJF minimizes average waiting time. However, it needs burst estimates (exponential averaging) and can starve long jobs. SRTF is the preemptive form of SJF.
  • RR gives each process a quantum in turn. As a result, it has bounded waiting, good response, and higher turnaround. Note that q must be large relative to a context switch. Weighted RR gives shares Ni/ΣN.
